# 输出格式

## 工作过程中

论文未完成前，如需汇报进展，保持简短：

```text
当前完成：
下一步：
风险或待确认：
```

除非用户要求，不要把所有中间表格、探索笔记或代码日志堆进对话。

## 最终交付

最终回答应提供完整论文，或提供完整论文文件路径。支撑代码、图表和附录只能在论文完成后作为辅助材料说明。

若最终交付为 Word 文档，正文中的数学公式必须是 Word 可渲染的公式对象。优先使用 LaTeX 数学表达式生成 Word/OMML 公式，不要把公式作为普通文本、截图或不可编辑图片插入。

最终论文正文应不少于 30 页，且不能依靠附录、空白、原始数据堆叠或代码灌水凑页数。正文长度应来自充分的图表分析、公式推导、算法原理、模型检验、敏感性分析和结果解释。

论文图表数量和视觉密度应接近参考优秀论文。图表必须清晰、美观、编号连续、单位完整，并在正文中解释其支撑的结论。

## 论文骨架

除非赛题需要调整，否则使用以下默认结构：

```text
题目
摘要
关键词
一、问题重述
二、问题分析
三、模型假设
四、符号说明
五、数据预处理与可视化分析
六、模型建立与求解
七、结果分析与可视化
八、敏感性分析
九、模型检验
十、模型创新
十一、模型优缺点与改进方向
十二、结论
参考文献
附录
```

## 终稿检查

- 原题每个问题都已回答。
- 每个模型都有明确目的。
- 每个关键结果都有解释。
- 每张图都有图注、单位和论文角色。
- 正文不少于 30 页，且不是靠附录灌水。
- 图表数量充分，视觉效果接近参考优秀论文。
- 模型章节包含足够公式、算法底层原理和求解步骤。
- 敏感性分析支撑稳健性。
- 模型检验支撑可信度。
- 创新点具体且可辩护。
- Word 交付时，公式能在 Word 中正确显示且可编辑。
- 最终输出是一篇完整论文。
